## Typography

**No new sizes or weights.** Phase 1 set: 12 / 14 / 16 / 28 px, weights 400 / 700. Italic already exists (note column, band labels, `Not rolled yet`).

| Role | Size | Weight | Line Height | Phase 4 elements |
|------|------|--------|-------------|------------------|
| Display | 28px | 700 | 1.2 | Not used in Phase 4 |
| Heading | 16px | 700 | 1.2 | New `h2` `How these numbers are worked out` and `h2#explore-h` `Try this` (existing small-caps rule). Preset card titles `h3.explore-title` (prose 700, **no** small caps, `--ink`, `margin: 0`) |
| Body | 16px | 400 / 700 | 1.5 | Extended lede. `.explain` paragraphs (prose 400, bold lead-ins 700). Formula `dt` (prose 700). Formula rule lines (prose **italic** 400). Formula live lines (num 400, tabular; result `<b class="num">` 700). Preset descriptions (prose 400). Preset button label (prose 700, the same as the Roll button) |
| Label | 14px | 400 | 1.4 | Formula key lines (`dd.f-key`, prose 400, `--ink-muted`). Formula notes (`dd.f-note`, prose 400, `--ink`). Preset `Sets:` line (prose 400, `--ink-muted`). `#explore-status` (prose 400, `--ink`). Jump links line. `#explore` intro (existing `.section-intro`) |
| Small | 12px | 400 | 1.4 | Not newly used |

- **Formula typography [discretion] (D-03 "rule, then numbers"):** the **rule** lines are set in `--font-prose` *italic*, the traditional look of a math formula with named variables (`P(normal hit) × (avg die + D)`). The **live** lines are set in `--font-num` with `tabular-nums`, the page's number face (Phase 1 D-07). Two type treatments, no new token, so "rule" and "your numbers" never look alike. Digits inside the static rule lines (`21`, `20`, `2 ×`, `1 and 19`) are wrapped in `<span class="num">` so they are upright lining figures like every other number on the page (Georgia's figures are old-style).
- **Why not monospace:** a monospace stack would be a new font token, and the approved preview's `=` alignment is reproduced by a CSS grid column instead (see Formula Block), which is more robust than character counting because Georgia and system-ui have different widths.
- Generated explanation prose (`.explain`) follows the Phase 2 chart-caption precedent: one string rendered via `textContent`, with numbers inline in the prose font. Only the static bold lead-in is a separate `<b>` element.
- Prose measure: every new paragraph and formula block has `max-width: 72ch`.

## Component Contract: Formula Block (COPY-02, D-03, D-04)

**Rule: every substituted number is produced by the view-model from the same exact values and the same rounding as the card it explains (STAT-02).** The formula can never disagree with a card, because it prints the card's own string for every result.

| Group | `dt` | Rule lines (static, prose italic) | Key line (Label 14 muted) | Live lines (generated, num, result bold) |
|-------|------|-----------------------------------|---------------------------|------------------------------------------|
| `#f-hit` | `Hit chance` | `= d20 faces that hit / 20` · `= (21 − (AC − attack bonus)) / 20, kept between 1 and 19 faces` | `A natural 1 always misses and a natural 20 always hits, so it is always 1 to 19 faces: 5% to 95%.` | see Hit-chance variants |
| `#f-round` | `Expected per round` | `= P(normal hit) × (avg die + D) + P(crit) × (2 × avg die + D)` | live: `A normal hit is any hit except the natural 20. avg die = (8 + 1) / 2 = 4.5, and D is the damage bonus. A crit rolls the die twice and adds D once.` | see Expected variants |
| `#f-plus-hit` | `+1 to hit` | `= (avg die + D) / 20 per round: one more d20 face becomes a normal hit. 0 once capped.` | — | see +1 variants |
| `#f-plus-dmg` | `+1 to damage` | `= P(hit) per round: every hit deals 1 more.` | — | see +1 variants |
| `#f-plus-win` | `Which wins` | `+1 to hit wins only while avg die + D > 20 × P(hit).` | — | see +1 variants |

**Number formats (all exact, from integers):** P(normal hit) and P(hit) with 2 decimals (`0.50`, `0.55`; always multiples of 0.05). P(crit) `0.05`. `avg die`, `avg die + D` and `2 × avg die + D` with 1 decimal (always multiples of 0.5). Face counts as integers. Per-round results use **the stat card's own strings**: `perRoundText` (`2.700`, 3 decimals), `marg.hitRound` / `marg.dmgRound` (`0.225` / `0.550`). Percent uses `hitPct` (`55%`). Signs use U+2212, and a negative attack bonus is parenthesized: `(15 − (−2))`.

**Branch selection is by exact comparison, never by a hard-coded damage threshold [discretion]:** the view-model evaluates the closed form in integers and compares it with the engine's exact numerator. It uses the **rule branch** when they are equal and the **table branch** when they differ. This is exactly D-04's condition. It also covers the cases that a "D ≤ −2" shortcut gets wrong: at AC 25 / +0 / d12 / −2 the per-round closed form is still exact (0.550, only crits hit, and 2 + D ≥ 0).

Branches are mutually exclusive and are chosen in the order listed.

### Hit-chance variants (`#f-hit` live line)

With raw faces `F = 21 − (AC − atk)`:

| Case | Live line (default shown) |
|------|---------------------------|
| 1 ≤ F ≤ 19 | `= (21 − (15 − 5)) / 20 = 11/20 = ` **`55%`** |
| F > 19 (clamped, 95% cap) | `= (21 − (15 − 14)) / 20 → 20 faces, kept to 19 (a natural 1 always misses) = 19/20 = ` **`95%`** |
| F < 1 (clamped, nat-20 only) | `= (21 − (25 − 0)) / 20 → −4 faces, raised to 1 (a natural 20 always hits) = 1/20 = ` **`5%`** |

The face count equals the `Hit chance` card's sub-line (`11 of 20 d20 faces`), and the percent equals the card.

### Expected-per-round variants (`#f-round` live lines)

| Case | Live lines |
|------|-----------|
| Rule branch (closed form = exact). Default AC 15 / d8 / +5 / +0 | `= 0.50 × (4.5 + 0) + 0.05 × (2 × 4.5 + 0)` then `= 0.50 × 4.5 + 0.05 × 9.0 = ` **`2.700`** |
| Rule branch, negative D (AC 15 / d8 / +5 / −1) | `= 0.50 × (4.5 − 1) + 0.05 × (2 × 4.5 − 1)` then `= 0.50 × 3.5 + 0.05 × 8.0 = ` **`{perRoundText}`** |
| Rule branch, nat-20 only (AC 25 / d8 / +0 / +0) | `= 0.00 × (4.5 + 0) + 0.05 × (2 × 4.5 + 0)` then `= 0.00 × 4.5 + 0.05 × 9.0 = ` **`0.450`** |
| Table branch (closed form ≠ exact). AC 15 / d8 / +5 / −3 | Line 1 as above: `= 0.50 × (4.5 − 3) + 0.05 × (2 × 4.5 − 3)`. Line 2 is **replaced** by `dd.f-note`: `Not exact here: at a damage bonus of −3, some rolls would deal less than 0, but damage stops at 0. The table gives ` **`1.240`** ` per round, the same as the Expected per round card.` |

In the table branch no closed-form result is printed, so there is no number that disagrees with the card (D-04). The note's figure is the card's `perRoundText`.

### +1 variants (`#f-plus-hit`, `#f-plus-dmg`, `#f-plus-win` live lines)

Inputs: `DiceMath.marginals(p)` (`hitNum`, `dmgNum`, `reason`) and the card strings `marg.hitRound` / `marg.dmgRound`.

| Case | `+1 to hit` live | `+1 to damage` live | `Which wins` live |
|------|------------------|---------------------|-------------------|
| Rule branch, damage wins (default) | `= (4.5 + 0) / 20 = ` **`0.225`** | `= 11/20 = ` **`0.550`** | `Here 4.5 < 20 × 0.55 = 11.0, so ` **`+1 to damage wins.`** |
| Rule branch, hit wins (AC 15 / d8 / −2 / +2) | `= (4.5 + 2) / 20 = ` **`0.325`** | `= 4/20 = ` **`0.200`** | `Here 6.5 > 20 × 0.20 = 4.0, so ` **`+1 to hit wins.`** |
| Rule branch, equal (defensive: avg die + D is always x.5, so this cannot occur) | as above | as above | `Here 6.0 = 20 × 0.30 = 6.0, so ` **`they tie.`** |
| `reason = 'cap'` (AC 15 / d8 / +14 / +0) | `= 0: you already hit on 2+ (the 95% cap)` | rule or table branch | `Here +1 to hit adds nothing, so ` **`+1 to damage wins.`** |
| `reason = 'floor'` (AC 25 / d12 / +0 / +0) | `= 0: even with +1, only a natural 20 hits` | rule or table branch | same as cap |
| `reason = 'nodmg'` (AC 15 / d4 / +5 / −4) | `= 0, from the table: at a damage bonus of −4, a normal d4 hit deals 0` | table branch | same as cap |
| Table branch (AC 15 / d8 / +5 / −3) | `= ` **`0.095`** `, from the table: damage stops at 0 at this penalty, so the rule is off` | `= ` **`0.425`** `, from the table: damage stops at 0 at this penalty, so some hits gain nothing` | `Here 0.425 > 0.095 per round, so ` **`+1 to damage wins.`** · If the two **displayed** values are equal: `Here both add about 0.095 per round, so they are about even.` |

- The `Which wins` verdict compares the **displayed** tenths (`mHitT` vs `mDmgT`), the same convention as the Phase 2 readout gap, so the verdict and the two numbers above it always agree. In the rule branch the displayed values are exact, so the inequality and the verdict agree by construction: (avg die + D) / 20 vs P(hit) ⇔ avg die + D vs 20 × P(hit).
- The +1 to damage rule branch applies when `dmgNum === hitFaces × den`.

### Live-update behavior

The formulas are **not** live regions. They update in place on every render (`textContent`), like the stat cards, so a slider drag never announces anything. The stat cards already carry the numbers for assistive tech.

## Component Contract: Explanation Copy (COPY-01, COPY-03, COPY-04, D-02, D-05, D-06)

All copy is generated in the view-model (the preferred route in CONTEXT), from the values the page already computes. `VM.explainView(p, view)` returns `{ twoRolls, dmgLine, hitLine, crossLine }`. The chart parts come from the **same memoized `chartBase` result** (sweep, `crossings`, `attackBands`) that draws the markers, bands and caption. That result is extended, not re-derived (D-05).

**Voice (D-02):** two to four short sentences per spot, one idea per sentence, plain words. The rules are named only as far as the lesson needs (natural 1, natural 20, crit). A bonus is always `+N to hit` / `+N to damage` (Phase 2 naming). On-chart band names are quoted exactly as drawn: `“95% cap”` and `“only a nat 20 hits”` (U+201C / U+201D).

### Two-roll paragraph `#two-rolls` (COPY-01)

| Case | Copy (default values; everything in braces is live) |
|------|------------------------------------------------------|
| Normal threshold | `Every attack is two rolls, and the d20 comes first: with +5 against AC 15, a 10 or higher hits. Only a hit rolls damage: one d8, or two on a natural 20, and a miss deals 0. The table pairs all 20 d20 faces with all 8 damage faces, so its 160 cells are equally likely outcomes. That makes the average cell the expected damage per attack.` |

### Dashed-line paragraph `#explain-dmg` (COPY-04, linear)

Condition: `straightFrom` is the smallest k such that every damage-series step from k to 20 equals `hitFaces × den` (read from the sweep numerators).

| Case | Body after the lead-in **`The dashed line (+N to damage).`** |
|------|------------------------------------------------------------|
| Straight everywhere (`straightFrom = 0`). Default | `Each +1 to damage adds 1 to every hit. You expect 11 hits in 20 rounds, so every step adds the same 11.0 and the line is straight.` |
| Bent low end (AC 15 / d8 / +5 / −3 → from +2) | `Each +1 to damage adds 1 to every hit, but damage stops at 0, so at a damage bonus of −3 the first steps add less. From +2 on, every step adds the same 11.0: one for each of the 11 hits you expect in 20 rounds.` |
| One expected hit (nat-20 only) | `…You expect 1 hit in 20 rounds, so every step adds the same 1.0 and the line is straight.` (singular `hit`) |

The step is `hitFaces` with 1 decimal. It equals the marginal card's `+1 to damage … over 20 rounds` whenever the line is straight.

### Solid-line paragraph `#explain-hit` (COPY-04, plateau)

Sentence 1 always explains the step. Band sentences follow **only for bands drawn** (D-06, from `attackBands`), floor first (the caption order).

| Part | Copy (default values) |
|------|-----------------------|
| Step, D ≥ −1 (normal average = avg die + D) | `Each +1 to hit turns one more d20 face into a hit: one more hit in 20 rounds, worth an average d8 + 0 = 4.5.` |
| Step, floor bites on normal hits (normal average ≠ avg die + D), e.g. AC 15 / d8 / +5 / −3 | `Each +1 to hit turns one more d20 face into a hit: one more hit in 20 rounds, worth 1.88 on average here, since damage stops at 0.` (1.88 = the Average-damage card's `normal` sub-value) |

### Crossover paragraph `#explain-cross` (COPY-03)

### Click behavior (D-08)

1. The handler builds one patch `{ac, die, atk, dmg, n}`, passing **each value through `VM.parseControl(key, value, state[key])`** (the single parse path), then calls `setState(patch)` **once**. That makes one coalesced rAF render: controls, `<output>`, cards, formulas, all four tables, chart, explanations and sim all update in the same frame.
2. A rolled run goes stale by the normal comparison (Phase 3 D-08/D-09). Nothing re-rolls.
3. **No scrolling and no focus move [discretion].** Focus stays on the clicked button, so a keyboard user can try the next preset at once and the page never jumps under the reader. The chart is reached with the static `Go to the chart` link just below. Rationale: auto-scrolling a long page on click is disorienting and breaks the reader's place in the "Try this" text.
4. The handler writes `#explore-status` (see A11y): clear it, then set the text in the next `requestAnimationFrame`, so clicking the same preset twice announces again (the Phase 3 `#sim-status` pattern).
5. **The status line is kept honest by comparison:** `render()` clears `#explore-status` when the current `{ac, die, atk, dmg, n}` no longer equals the last-applied preset. `render()` only ever clears it and never writes new text, so no drag announces anything. Returning to the preset's values by hand does not bring the text back.
