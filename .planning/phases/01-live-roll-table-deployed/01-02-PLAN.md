## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local machine -> GitHub | OAuth token grants write access to the user's GitHub account |
| winget source -> local machine | Installed binary runs with the user's rights |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Information disclosure | gh OAuth token | mitigate | The user performs `gh auth login` in their own terminal; the token lives in Windows Credential Manager; the executor never runs `gh auth token`, `--show-token`, `env`, or `printenv`, and the SUMMARY is grep-checked for token patterns |
| T-01-06 | Spoofing | GitHub account identity | mitigate | OWNER comes only from `gh api user -q .login`, never guessed or typed by the executor |
| T-01-07 | Elevation of privilege | MSI install / UAC | accept | UAC approval is the user's decision; the executor does not bypass or retry elevation |
| T-01-SC | Tampering (supply chain) | winget install of GitHub.cli | mitigate | `--id GitHub.cli --source winget --exact` pins the official package id from the official source (publisher GitHub Inc, RESEARCH Package Legitimacy Audit: Approved); no npm/pip/cargo installs in this phase |
</threat_model>
