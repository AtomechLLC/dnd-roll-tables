# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **This contract extends `01-UI-SPEC.md` and `02-UI-SPEC.md`.** Everything they lock stays as it is: fonts, the 4-size / 2-weight type scale, spacing tokens `--sp-1..6`, surface/ink/accent/heat/miss/series tokens, table tiers, legend classes, the `.section-intro` pattern, and the focus ring. This file adds only what Phase 3 needs.
> Sources: 03-CONTEXT.md (D-01..D-16, locked), ROADMAP Phase 3 success criteria 1–4, REQUIREMENTS SIM-01..06, ARCHITECTURE.md Pattern 4, FEATURES.md T9/D7/D8, `index.html` (style block and section markup as of commit 08faa58). Values marked **[discretion]** were chosen here under CONTEXT.md "Claude's Discretion". Each has a one-line rationale. No user questions were needed. Every open point was either locked upstream or settled by an existing pattern.

## Design System

| Property | Value |
|----------|-------|
| Tool | none. Vanilla HTML/CSS/JS in one `index.html`. Not React, so the shadcn gate does not apply. |
| Preset | not applicable |
| Component library | none. Native `<button>`, `<table>`, and `<p>` / `<div>`. This is the page's **first `<button>`**. |
| Icon library | none. Text and Unicode only (`±`, `×`, `—`, `·`, `−`). No dice glyphs or emoji (font support varies, and CSP blocks icon fonts). |

**Component dimensions (all multiples of 4):**

## Color

The Phase 1 60/30/10 split is unchanged. **No new tokens.**

| Role | Token | Phase 3 usage |
|------|-------|---------------|
| Dominant (60%) | `--paper` | Section background, simulated figure card fill, log table background, mark-ring inner halo, badge text |
| Secondary (30%) | `--surface` | Exact figure card fill (echoes the focal "Expected over 20 rounds" stat card), log header row, disabled button fill |
| Accent (10%) | `--accent` | See the reserved list below |
| Destructive | — | None. Phase 3 has no destructive actions. Rolling again replaces the run, and the previous total stays visible in the tally, so nothing is lost. |
| Text | `--ink` | Figure values, result lines, log text, 3px top rule of the exact card, 2px total rule of the log, mark ring, badge fill |
| Muted | `--ink-muted` | Figure labels, `± SD`, `Not rolled yet`, foot line, dashed frame of the simulated card, miss words in the log, **all stale text** |
| Hairline | `--line` | Card borders, log row rules, stale-state card frames |

**Accent reserved for (exhaustive: the Phase 1/2 list plus two additions):**
1. Focus ring on every control (`:focus-visible`), including the new Roll button.
2. The checked die segment.
3. Range sliders (`accent-color`): AC and N.
4. The crit row (d20 = 20) bottom rule and `crit*` note text, in all four outcome tables.
5. The crit swatch in the legend.
6. **New:** the Roll 20 rounds button fill (`--accent` background, `--paper` text: 5.95:1 light, 9.6:1 dark, the same pair as the checked die segment), including its hover and pressed mixes.
7. **New:** the word `crit` in the log's Result column (700). It matches the table's crit convention (item 4).

Accent is **not** used for the figures, marks, badges, tally, stale note, or `Now:` line.

**Mark ring contrast (D-11, "reads on every heat color").** A mark is a two-tone ring: 2px `--ink` at the cell edge and a 1px `--paper` halo just inside it. At every heat value, at least one of the two tones contrasts strongly with the cell. Light theme: ink on `--heat-lo` (pale) is about 12:1, and paper on `--heat-hi` (crimson) is about 7:1. Dark theme: the tokens swap roles (ink light, paper dark), so the same holds. The ring is also a shape, so it does not rely on color.

**Stale dimming [discretion]:** stale text switches to `--ink-muted` (6.2:1 on surface and more on paper). Frames switch to `--line`. **Never use `opacity`.** Opacity would drop stale text below 4.5:1, and stale content still has to be readable.

## Layout Contract (D-01, D-02)

Page order: controls → stats → `#tables` → `#compare` → `#chart` → **`#sim`** → footer. Nothing above `#sim` moves or changes size, with one exception: the one static legend item added to the `#tables` legend (see Marks).

```
<section#sim aria-labelledby="sim-h">       container: sim / inline-size
    h2#sim-h
    p.section-intro
    div.sim-body                             grid: 1 column; 2 columns at >= 54rem
        div.sim-result                       left column (max-width 32rem)
            p#sim-note.sim-note     [hidden until a run exists]  rolled-at note
            div.sim-pair                     grid auto-fit minmax(12rem, 1fr), gap 16px
                div.fig.fig-exact            label / value / foot   (subgrid, 3 rows)
                div.fig.fig-sim              label / value / button (subgrid, 3 rows)
                    button#roll.btn-roll type="button" disabled
            p#sim-spread.sim-line            spread line (always shown when the engine works)
            p#sim-place.sim-line             placement line, or the empty-state prompt
            p#sim-now.sim-line      [hidden unless stale]
            p#sim-tally.sim-line    [hidden unless fresh and >= 2 runs]
            p#sim-status.vh role="status"    written ONLY by the click handler
        div.sim-log-wrap            [hidden until a run exists]   right column
            table#sim-log.sim-log aria-describedby="sim-note"
                caption / thead (static) / tbody (empty in markup) / tfoot (empty in markup)
```

- **Section rhythm:** `h2` → 16px → intro (`.section-intro`, existing: Label 14 / 400 / muted, max 72ch, 16px bottom margin) → `.sim-body`.
- **`.sim-body`:** `display: grid; grid-template-columns: minmax(0, 1fr); gap: var(--sp-4);`. At `@container sim (width >= 54rem)`: `grid-template-columns: minmax(0, 32rem) auto; column-gap: var(--sp-5); align-items: start;`. The named container follows the Phase 2 practice (named queries cannot be captured by a wrapper). The log sits to the right of the result on laptops and below it on phones and tablets.
- **`.sim-result`:** `display: grid; gap: var(--sp-2);` with `margin-top: var(--sp-2)` on the first `.sim-line` after the pair, which gives 16px from pair to spread line.
- **`.sim-pair`:** `display: grid; grid-template-columns: repeat(auto-fit, minmax(12rem, 1fr)); gap: var(--sp-3); max-width: 32rem;`. Each `.fig` has `grid-row: span 3; grid-template-rows: subgrid;` (the same technique as `#stats`), so labels, values, and the third row line up side by side.
- **`.fig`:** `display: grid; gap: var(--sp-2); padding: var(--sp-3); border-radius: 8px; align-content: start;`
  - `.fig-exact`: `background: var(--surface); border: 1px solid var(--line); border-top: 3px solid var(--ink);`. This matches the focal stat card, because it is the same number.
  - `.fig-sim`: `background: var(--paper); border: 1px dashed var(--ink-muted);`. The dashed frame means "a sample, not a law".
  - `.fig .label`: Label 14 / 400 / `--ink-muted`.
  - `.fig .value`: Display 28 / 700 / num / `--ink`, `line-height: 1.2`, `white-space: nowrap` per part. The exact value is `<span class="num">54.0</span> <span class="sd">± 14.2</span>`. `.sd` is Body 16 / 400 / num / `--ink-muted`. Line breaks may only fall between the two spans, so a phone can put `± 40.5` on its own line.
  - `.fig-exact` third row: `p.foot`, Small 12 / 400 / `--ink-muted`.
  - `.fig-sim` third row: the Roll button, `justify-self: start`.
- **`.sim-line`:** `margin: 0; max-width: 72ch;` Body 16 / 400 / prose / `--ink`. Numbers use `<b class="num">` (num, tabular, 700).
- **`.sim-note`:** `margin: 0;` Label 14 / 400 / `--ink`. The stale sentence is a `<b>` (700). It is always present once a run exists: fresh, it states the rolled-at settings, and stale, it adds one sentence. Showing it in both states means the pair does not jump down the first time a setting changes. At `@container sim (width < 40rem)` it reserves `min-height: calc(2 * 1.4em)`, so adding the stale sentence never adds a line while the user drags.
- **Log (`.sim-log`):** `border-collapse: collapse; table-layout: fixed; width: 296px;` on `--paper`.
  - `caption`: `caption-side: top; text-align: left;` Label 14 / 700 / `--ink`, `padding-bottom: var(--sp-2)`.
  - `th, td`: `height: 24px; line-height: 24px; padding: 0 var(--sp-2); border-bottom: 1px solid var(--line);` Label 14 / num / tabular.
  - `thead th`: `--surface`, 700, `--ink`. Numeric columns are right-aligned, and Result is left-aligned.
  - `tbody th[scope="row"]` (round number): 400, right-aligned, no fill (row labels, not header styling).
  - Right-aligned: Rnd, d20, Dice, Dmg. Left-aligned: Result (prose 400; `crit` in 700 `--accent`; `miss` in `--ink-muted`; `hit` in `--ink`).
  - `tfoot tr`: `border-top: 2px solid var(--ink)`. `th` `Total` spans the first four columns (`colspan="4"`, left-aligned, 700). `td` is the total (700, right-aligned).
- **Phone (360px viewport, 328px content) [discretion]:** the pair stacks (192 × 2 + 16 > 328): exact card first, then the simulated card with the button. Result lines wrap normally. The log (296px) sits below the result at 24px. There is never horizontal page scroll. Rationale: the figures are the lesson, so they get full width before the log.

| Part | Spec |
|------|------|

## Component Contract: Result Block (SIM-02, SIM-05, D-03, D-04, D-05)

**Exact vs simulated must never share styling (D-03). The cues, none of them color:**

| Cue | Expected (exact) | This run (simulated) |
|-----|------------------|----------------------|
| Label wording | `Expected (exact)` | `This run (simulated)` |
| Frame | Solid, `--surface` fill, 3px ink top rule (like the focal stat card) | Dashed 1px border, `--paper` fill, no top rule |
| Number format | One decimal plus a spread: `54.0 ± 14.2` | Whole number, no spread: `61` (a real 20-round total is always an integer) |
| Third row | Foot line explaining `±` | The Roll button |

**Numbers (display-consistent, the same rules as Phase 2 deltas):**
- Expected: `VM.tenths(e20Num, e20Den)` via `VM.fixed(…, 1)`. It is identical to the "Expected over 20 rounds" stat card (STAT-02).
- SD: exact `sqrt(20 × Var(one round))` from the `DiceMath` enumeration with a true 2dX crit (D-05), rounded to tenths once.
- Spread bounds: **displayed expected tenths ± displayed SD tenths**, so a reader can check them by hand. `54.0 ± 14.2` → `39.8` and `68.2`. The lower bound is clamped at `0.0`.
- Placement: `diff = realized × 10 − expected tenths`. Magnitude is shown with one decimal. `SD multiple = |diff| / SD tenths`, rounded to one decimal. `diff = 0` → the "exactly on" wording.
- Integers only in the simulated figure, the log, and the tally totals.

**Reference values (checked in this session):**

| Settings | Expected ± SD | Spread line |
|----------|---------------|-------------|
| AC 15, d8, +5, +0 (default) | `54.0 ± 14.2` (Var one round 10.035) | `About 2 runs in 3 land between 39.8 and 68.2.` |
| AC 16, d8, +5, +0 | `49.5 ± 14.1` | `About 2 runs in 3 land between 35.4 and 63.6.` |
| AC 30, d4, −5, −5 (clamp) | `0.6 ± 1.1` | `Most runs land between 0.0 and 1.7 (damage cannot go below 0, so the spread is lopsided).` |

## Component Contract: Marks on the Big Outcome Table (D-11, D-12, D-13)

`renderOutcomeTable` gains an optional `marks` argument that **only the `#outcome` call passes**. The three compact tables never receive it. Marks are derived at render time from the stored run, so a later full repaint cannot wipe them. They are passed only when a run exists **and is not stale**.

| Outcome rolled | Where the mark goes | Mark |
|----------------|---------------------|------|
| Normal hit `(d20 = r, face = k)` | The `td` at row r, column k | Class `roll` → ring. If the cell was rolled 2+ times, `data-n="2"` → badge `×2`. No badge at 1 (D-11). |
| Crit (d20 = 20) | The **row header** `th` of row 20, never a cell (D-12) | Class `roll` + `data-n` → ring and badge, **always including `×1`** |
| Miss or nat 1 (d20 = r) **[discretion]** | The **row header** `th` of row r | Same as crits: ring and badge, always including `×1` |

- **Rationale for always badging row labels:** a row label stands for a whole row of possible outcomes, not one cell, so the count is always stated (D-12's "crit ×1"). Together with the existing note `crit*`, row 20 reads "20 ×1 … crit*". Counts live on the row header rather than in the note column because `auto-miss ×2` would overflow the 64px narrow-tier note column.
- **Ring CSS:** `.outcome .roll { position: relative; }` and `.outcome .roll::before { content: ""; position: absolute; inset: 0; border: 2px solid var(--ink); box-shadow: inset 0 0 0 1px var(--paper); pointer-events: none; }`. The ring is drawn by a pseudo-element, so it never touches the cells' own `box-shadow` (threshold and crit rules) and causes no layout shift. The interior stays at least 14 × 14px at the narrow tier, so the damage number stays readable.
- **Badge CSS:** `.outcome .roll[data-n]::after { content: "×" attr(data-n) / ""; position: absolute; top: -6px; left: 50%; translate: -50% 0; z-index: 1; height: 12px; min-width: 16px; padding: 0 4px; border-radius: 4px; background: var(--ink); color: var(--paper); font: 700 12px/12px var(--font-num); font-variant-numeric: tabular-nums; text-align: center; white-space: nowrap; }`. The badge straddles the top edge, so it clears the cell's own digits and the digits of the row above at all three tiers. **Exception:** in the first body row (d20 = 1) it straddles the bottom edge (`top: auto; bottom: -6px`), so it never covers the header corner. The empty alt text (`/ ""`) keeps the badge out of the accessibility tree (see A11y).
- **Legend item (static, always present) [discretion]:** appended to the `#tables` legend after the threshold item. The swatch is `.swatch.h.roll` with `--t: 0.25`, shows the ramp's t = 0.25 value, and has `data-n="2"`, so the real ring and badge classes draw it and cannot drift. Text is in Copywriting. It is always present, so rolling or clearing marks never reflows the legend or shifts the table while a slider is dragged at the top of the page.
- **Clearing (D-13):** when the run goes stale, `marks` is not passed, and the next render draws a clean table. If the settings return to the rolled-at values (D-09), the marks come back, because they again point at the correct cells.
- **Caption suffix for assistive tech:** when marks are shown, the `#outcome` caption gets a `.vh` suffix (see Copywriting). The log is the full accessible record of the run.

## Interaction Contract (SIM-01, SIM-04, D-08..D-10, D-13)

| Event | Behavior |
|-------|----------|
| Page load | Nothing rolls (SIM-04). The exact figure and spread line show the current settings live. The simulated slot shows `Not rolled yet`. The note, `Now:`, tally, and log are hidden. The table has no marks. |
| Click `Roll 20 rounds` | `simulate(params, 20, Math.random)` is called in the click handler, which is the only place `Math.random` is passed in. The run `{id, rounds, total, params}` is stored in state, the tally is updated, then `scheduleRender()` runs. After that it writes the status sentence (see A11y). Rolling is instant (D-07). |
| Tally update | If the new run's params equal the tally's params, `unshift(total)` and keep 5. Otherwise reset the tally to `[total]` with the new params. |
| Control change: AC, die, attack bonus, damage bonus | These are "changing the attack". `render()` compares the run's params with the current `{ac, die, atk, dmg}`. If they differ, the run is **stale**: `#sim` gets class `is-stale`, the note adds its stale sentence, `Now:` is shown, the tally is hidden, the log caption gets the rolled-at suffix, and the table marks are not passed. The exact card keeps the **rolled-at** expected ± SD (D-08). Nothing re-rolls. |
| Control change: compare `+N` slider | **Not** "changing the attack" [discretion, per CONTEXT]. The run stays fresh, and the marks and tally stay. |
| Returning to the rolled-at settings | The run un-stales (D-09): the class is removed, the note and caption drop their stale parts, `Now:` hides, and the marks and tally reappear. |
| No flicker while dragging (SC3) | `renderSim` rebuilds the figures, log rows, and total **only when `run.id` changes** (it caches the last rendered id). On every other render it only toggles `is-stale`, the note's stale sentence, and `hidden` flags, and it sets the `Now:` line text. Before any run, it updates the exact figure and spread text in place (plain `textContent`, like the stat cards). No transitions, no animation. |
| Keyboard | Tab order: … → N slider → **Roll 20 rounds**. The log and figures are not focusable. |
| Motion | None anywhere in the section, so reduced-motion handling does not apply. |

## Accessibility Contract

| Item | Decision |
|------|----------|
| Live region | **Only** `p#sim-status.vh role="status"` (implicit `aria-live="polite"`, atomic). It is written **only by the click handler**, never by `render()`, so slider drags announce nothing new here (the existing `<output>` still announces N). To make identical results re-announce, the handler sets `textContent = ''` and then writes the sentence in the next `requestAnimationFrame`. |
| Announced text | See Copywriting (`Rolled 20 rounds: …`). |
| `.sim-result` and figures | Not live regions (they update live before the first roll and during drags). |

| Button | Native `<button>`, name = visible text, `disabled` only when the engine failed. |
| Marks | The ring is decorative. The badge uses CSS alt text `""`. The `#outcome` caption gets the `.vh` suffix while marks are shown. The log is the complete accessible record. |
| Non-color cues | Exact vs simulated: wording, frame, and format. Stale: note sentence and caption suffix. Marks: ring shape and `×N` text. Log results: words. |
| Target size | Button ≥ 40px tall, well above WCAG 2.5.8's 24px minimum. |

## States

| State | What the user sees |
|-------|--------------------|

## Copywriting Contract

Conventions carry over: U+2212 minus, `·` separators, signed values via `VM.signed`, one-decimal expected figures via `VM.fixed(tenths, 1)`, and U+00D7 `×`. Settings are always phrased **`AC 15, d8, +5 to hit, +0 damage`** (the same order as the controls, with Phase 2's "to hit / to damage" naming).

| Element | Copy |

## Assumptions (decided under Claude's Discretion, flagged for the checker and planner)

| # | Assumption / choice | Rationale | If wrong |
|---|---------------------|-----------|----------|
| A1 | The Roll button lives in the simulated card's third row, not above the section | D-02 pairs the button with the "Not rolled yet" slot. The action sits next to the result it produces. | Move it into a `.strip` between the intro and `.sim-body`. Nothing else changes. |
| A2 | Misses and nat 1s mark their d20 row header like crits do, always with a `×k` badge | CONTEXT's recommended approach. No die was rolled, so no cell can be right. | Mark nothing for misses. The log still lists them. |
| A3 | Marks and the tally come back when the settings return to the rolled-at values | D-09 makes staleness a comparison, and marks derived from a fresh run point at the right cells | Make D-13 one-way: delete the marks and tally on the first change |
| A4 | Tally shows totals only (newest bold) with the expected value appended, and only when there are ≥ 2 runs | The appended expected value anchors the comparison without ▲/▼ markers. One entry would just repeat the figure. | Add a signed deviation after each total |
| A5 | The log uses `<th scope="row">`, which is safe for check-page's 80 count because it is empty at load | Better table semantics | Use `<td>` for round numbers and leave check-page untouched |
| A6 | h2 is `20 rounds, rolled for real` | Avoids a heading and a button with the same name | Any heading that does not repeat the button text |
| A7 | Dimming is `--ink-muted` text plus `--line` frames, never opacity | Keeps stale text at or above 4.5:1 | None. This is a contrast requirement. |
| A8 | Spread bounds and placement use displayed tenths (the Phase 2 delta convention) | The printed numbers add up by hand | Compute from exact values. They may then differ by 0.1 from the printed E ± SD. |
