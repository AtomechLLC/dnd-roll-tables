## Phase Goal

**As a** game designer, **I want to** roll 20 real rounds at the current settings and compare the realized total with the exact expectation and its spread, **so that** I learn not to over-trust averages while the exact and simulated numbers never blur together.

<objective>
Ship the first vertical slice of the simulation: a "Roll 20 rounds" button at the bottom of the page that rolls real dice and shows "This run (simulated)" next to a visually distinct "Expected (exact)" figure with its exact standard deviation, a spread line, and a placement line. Underneath: the exact variance enumeration, the seeded simulator block, the view-model copy helpers, seeded self-test checks, full-domain and large-sample dev checks, and the WR-01 guarded first render that the button's enable-after-render contract depends on.

Purpose: After this plan a designer can click the button and see how far one fight lands from the average. SIM-01, SIM-02, SIM-05, and SIM-06 are complete.
Output: index.html (engine, dice-sim block, VM, section markup, CSS, app wiring, self-test, UI smoke), tools/check-engine.mjs, tools/check-page.mjs.

Out of scope for this plan (later plans in this phase): the per-round log, the rolled-at note, stale dimming, the "Now:" line, and the tally display (plan 03-02); the marks on #outcome and the legend item (plan 03-03). rollWith already maintains sim.tally, so plan 03-02 only renders it. No push, gh, or Pages work (user memory: GitHub deploy deferred).

Deviation to record in the SUMMARY: the spread line uses the lopsided wording when E − SD < 0 **or** when only a nat 20 hits (stats.hitFaces === 1). The UI-SPEC rule (only E − SD < 0) would print "About 2 runs in 3" for 9,520 nat-20-only settings where the band holds only 45.5% of runs (RESEARCH Pitfall 1, Open Question 1). This falls within CONTEXT discretion ("the spread line when E − SD falls below 0 … word the line accordingly") and is guarded by check-engine invariant (p).
</objective>
