# Quick 260927-17o: Settings and outcome table at the top Summary

The outcome table (`section#tables`) now sits directly under the controls strip and above the stat cards. The crit footnote's floor sentence now points down to the stat cards, and a new check-page guard (14) fails if the section order drifts.

## Layout decision reversal

The user previewed the page and asked: "I would like the settings and the outcome table at the top please." This reverses:
- Phase 1 D-01 ("stat cards directly beneath controls")
- Phase 2 D-02
- Phase 4 D-01 page order ("Page order is unchanged", 04-UI-SPEC Layout Contract)

The historical phase docs were left as they are. New order: header, form#controls, section#tables, section#stats (six cards + #formulas + #marginal), #compare, #chart, #sim, #explore.

## Changes

- **index.html**: moved the 9-line `section#tables` block with its markup unchanged. In `renderFootnote`, the floor sentence changed from 'The stats above use the real two-dice rule.' to 'The stat cards below use the real two-dice rule.' The preceding "doubled-face shortcut" sentence is byte-identical. `PAINTED_SECTIONS` is now in page order (cosmetic). No CSS change was needed, and nothing was added to the self-test or the ?test smoke.
- **tools/check-page.mjs**: guard (14) is in the header comment. The check runs after the fault/else split, so it runs in every mode. It prints `got <actual order>` on failure. The fault-branch section list is reordered (cosmetic).
- README.md already lists the outcome table before the stat cards and says "A short paragraph above the table", so it needed no edit.

- `check-page` modes ?test, --plain, --width 1366, --width 390 and --fault render all print CHECK-PAGE PASS, with `ok page order: ...` in each. a11y (11) tab order passes unchanged. --fault render hides all six sections, including the moved #tables. Chrome self-test runs in 47-56 ms.
- The `--expect` regression passed for all 6 strings ("Outcome table", "a 10 or higher hits", "160 cells", "How these numbers are worked out", "11/20 = 55%", "Go to the chart").
- **Bite proof:** I ran check-page on a scratch copy of the pre-change HEAD index.html (old order). It printed `CHECK-PAGE FAIL: page order: ...` with `got header, form#controls, section#stats, section#tables, section#compare, ...`. The scratch copy was deleted.
- `check-engine`: CHECK-ENGINE PASS on all 4 runs (251/251, 70,980 combos). Node self-test times: 210.0, 253.8, 209.0 and 212.9 ms, all above the 200 ms budget. The script prints this as a WARNING, not a failure. **The cause is machine load, not this change:** the sweep took 51-58 s against the usual ~34 s. Re-run check-engine on an idle machine before the 04-05 publish to confirm it is back at or under 200 ms.
